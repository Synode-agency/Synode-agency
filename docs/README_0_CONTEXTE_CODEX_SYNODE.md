## 2. Synode en une phrase

> **Synode conçoit, intègre et opère des systèmes IA sur mesure pour les PME.**

Formulation secondaire :

> **Agents IA, automatisations et logiciels métier connectés aux outils et aux données du client, avec contrôle humain et suivi dans le temps.**

Principe fondateur :

> **Le problème avant la technologie.**

Synode ne vend pas l’IA pour vendre de l’IA. Nous partons d’un problème métier concret, puis nous construisons la solution adaptée.

---

## 3. Ce que Synode n’est pas

Ne pas présenter Synode comme :

- une simple agence d’automatisation ;
- un vendeur de chatbots ;
- une agence no-code ;
- une agence web classique avec une couche « IA » ;
- une entreprise développant ses propres modèles fondamentaux ;
- une structure qui livre un prototype puis disparaît.

Synode utilise les technologies IA existantes pour construire des systèmes utiles, intégrés, contrôlables et maintenables.

## 5. Logique Build + Run

Synode doit progressivement être capable d’accompagner une solution sur toute sa vie :

> **Comprendre → Construire → Intégrer → Opérer → Améliorer**

Cela signifie :

- comprendre le processus réel ;
- construire la solution ;
- la connecter aux outils et données ;
- la mettre en production ;
- assurer le suivi prévu ;
- améliorer la solution lorsque les besoins ou les technologies évoluent.

---

## 6. Exploitation, maintenance & monitoring

Ce n’est pas une septième offre. C’est la continuité naturelle d’une solution lorsque cet accompagnement est prévu au contrat.

Une solution peut générer des coûts récurrents : API IA, hébergement, bases de données, stockage, services externes, monitoring et outils tiers.

Synode peut assurer selon le projet :

- surveillance ;
- maintenance ;
- corrections ;
- optimisation ;
- suivi des coûts ;
- amélioration des agents ;
- adaptation à de nouveaux modèles ;
- support ;
- petits ajustements.

Les évolutions importantes sont chiffrées séparément.

## 7. Différenciation à construire

Synode ne doit pas chercher sa différence en ajoutant continuellement de nouvelles catégories de services.

La différenciation doit progressivement reposer sur :

1. compréhension fine des processus métier ;
2. construction sur mesure ;
3. intégration dans l’environnement réel du client ;
4. contrôle humain lorsque nécessaire ;
5. monitoring et maintenance ;
6. proximité directe avec les fondateurs ;
7. démonstrateurs et preuves concrètes ;
8. composants techniques réutilisables.

Positionnement de fond :

> **Synode transforme des processus qui ralentissent une entreprise en systèmes IA réellement opérationnels.**

## 8. Cible prioritaire

Synode reste multi-sectoriel à ce stade. La spécialisation prioritaire porte sur un **type de problème**, pas sur un secteur.

### ICP prioritaire

> **PME de services dont les équipes passent beaucoup de temps entre emails, documents, CRM, tâches administratives et logiciels déconnectés.**

Problèmes particulièrement pertinents :

- tâches répétitives ;
- pertes de temps ;
- copier-coller et doubles saisies ;
- beaucoup d’emails ou de documents ;
- données dispersées ;
- logiciels mal connectés ;
- validations manuelles ;
- suivi commercial chronophage ;
- connaissances internes difficiles à retrouver.

Les secteurs peuvent être testés sans enfermer Synode : services B2B, immobilier, recrutement, comptabilité, construction, transport, cabinets professionnels, commerce, etc.

## 13. Règles UX et éditoriales

### Cas d’usage

La section « L’IA dans votre quotidien » doit rester simple. Chaque card doit faire comprendre rapidement :

1. le problème ;
2. ce que Synode peut faire ;
3. le bénéfice attendu.

Privilégier le langage métier au vocabulaire technique.

### Confiance & sécurité

Présenter sans inventer de certification :

- confidentialité ;
- contrôle humain ;
- intégration ;
- suivi technique.

Ne pas promettre une sécurité absolue, une conformité automatique ou une localisation de données non vérifiée.

### Réalisations

- Projet interne = indiqué comme tel.
- Démonstrateur = indiqué comme tel.
- Projet client = seulement après projet réel et autorisation.
- Aucun témoignage, logo, chiffre ou résultat inventé.

## 15. SEO

Objectif prioritaire : améliorer le référencement naturel de Synode sur Bruxelles et la Belgique autour de recherches cohérentes avec l’offre, notamment :

- agence IA Bruxelles ;
- agence IA Belgique ;
- solutions IA Belgique ;
- agents IA Bruxelles / Belgique ;
- automatisation PME Belgique ;
- logiciel IA sur mesure Belgique.

Le SEO doit rester utile et naturel : technique, local, sémantique, on-page, données structurées, sitemap, métadonnées, performances et maillage interne.

### Règle SEO permanente pour chaque section

Toute nouvelle section ou modification importante de contenu doit intégrer le SEO dès sa conception :

1. définir l’intention de recherche à laquelle la section répond ;
2. utiliser un titre `h2` descriptif et des `h3` qui expliquent précisément le sujet ;
3. employer naturellement les expressions que le prospect utiliserait, avec leurs variantes sémantiques ;
4. apporter une réponse utile, concrète et propre à Synode, plutôt qu’un paragraphe écrit uniquement pour Google ;
5. utiliser des liens internes dont le libellé décrit réellement la destination ;
6. intégrer Bruxelles ou la Belgique uniquement lorsque le contexte local est pertinent ;
7. garder les versions FR et EN cohérentes sans traduire mécaniquement les mots-clés ;
8. vérifier la hiérarchie des titres, les métadonnées, le maillage et les données structurées concernées.

Chaque section possède une intention principale différente. Ne pas répéter « agence IA Bruxelles » ou « solution IA sur mesure » dans tous les titres : la diversité sémantique, la clarté et l’utilité priment sur la densité de mots-clés.

Ne pas produire des dizaines de pages faibles uniquement pour cibler des mots-clés.
